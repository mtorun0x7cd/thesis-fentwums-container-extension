# Changelog

All notable changes to this repository are listed here. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). The first entry is the record tag `epub-3597`; from 1.1.0 on, the versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html) and cover the code, the data and the documentation. The text of the thesis changes only through [`ERRATA.md`](ERRATA.md).

This repository was recreated with a new history on 2026-10-02; the earlier release, v1.0.0 of 2026-08-01, was not the version of record and is withdrawn. Its PDF was built by CI from the sources of that day and was not the deposited thesis.

## [1.1.0] - 2026-10-02

### Added

- `README.md`: the thesis, its publication, a summary of the work, the contents, the pinned software, how to reproduce the thesis and the evaluation, the limitations, the corrections, the citation and the licences.
- `ERRATA.md`: the known errors of the deposited thesis, the properties of its catalogue record and of the deposited file, and the web addresses of the thesis that have moved.
- `evaluation/README.md`: every quantitative statement of Chapter 6 with its evidence and kind, the provenance of the results of the three machines, the terms and the rerun recipe.
- `evaluation/harness/packages.lock.upstream-1884317.json`: the restore lock file of the harness as the extension repository held it at commit `1884317`, the state of the macOS measurement on 2026-06-30, kept as evidence. Restore does not read it.
- `evaluation/harness/packages.lock.json`, the restore lock file of the harness, and the property `RestorePackagesWithLockFile` in its project file. Both postdate the measurements: the lock file was written on 2026-10-05 with the .NET SDK 10.0.301, the SDK of the measurements, and `dotnet restore --locked-mode` of the harness passes against it under that SDK and under 10.0.401.
- `evaluation/benchmarking_suite/results/supplementary/shared-image-control/`: the original files of the cross-host control of Section 6.5.3, in which the image of Machine 3 ran unchanged on Machine 1 on 2026-07-02. They were found in 2026 and are added unchanged; `evaluation/README.md` gives their bytes, SHA-256 and dates.
- `scripts/check_result_statistics.py`, which recomputes the statistics of every result file from its raw times with the functions of `benchmark.py`; `make aggregate-check` runs it before it recomputes the tables.
- `SECURITY.md`, `CONTRIBUTING.md`, the correction form, the workflows, the opt-in pre-commit hook in `.githooks/`, which scans staged changes with `gitleaks git --staged`, the social card and the scripts that check the metadata and the links.

### Changed

- `CITATION.cff` and `codemeta.json` carry the version 1.1.0.

### Fixed

Statements in files that the record tag `epub-3597` holds, corrected here; the tag keeps them as they were:

- `CITATION.cff` and `codemeta.json`: the submodules are pinned at their state when the thesis was submitted; the tag says at the state the thesis describes, though the thesis names no commit of them.
- `codemeta.json`: the reference publication is typed `schema:Thesis` and its language is given as `schema:inLanguage`, because the CodeMeta 3.0 context defines neither `Thesis` nor `inLanguage`; and the software requirements are `SoftwareApplication` nodes with a name, because the context reads a plain string there as an IRI, with the SDK as `evaluation/global.json` allows it, 10.0.300 or any later 10.0 SDK, where the tag says 10.0.300 or later.
- `NOTICE` and `REUSE.toml`: the README and `CITATION.cff` quote the abstract of the thesis, and `CITATION.cff` and `codemeta.json` its title and printed keywords; the tag says that `CITATION.cff` and `codemeta.json` quote the abstract.
- `REUSE.toml`: the files under `evaluation/` carry their licence there, so that no header changes them, and `evaluation/README.md` lists the scripts and figures that changed after the measurements; the tag says that the apparatus is kept byte for byte as it was measured, though Machine 1 ran an earlier state of `benchmark.py` and `run_evaluation.py`, and `aggregate.py`, `evaluation/integration/run_harness_smoke.sh` and the three figures changed after the measurements.
- `NOTICE`: `evaluation/integration/run_harness_smoke.sh` entered the extension on 2026-06-28, not with the other fixtures on 2026-06-12; the SHA-256 of `ice40_blink.v` and `ecp5_blink.v` stands in the result files of the two synthesis workloads, not in every result file; the earlier repository stated the MIT License for what its author wrote, the mark of TH Köln and the submodules excepted, not for all of its content; and of the example projects, the pin constraints of `03_counter` to `07_uart_tx` were first committed in the earlier repository of this thesis on 2026-07-12, and the README files were revised after 2026-06-28, where the tag says that the projects with their pin constraints were committed to the extension on 2026-06-28.
- `publication/README.md`: the deposited file was processed outside this repository, among other things linearised and given new metadata, where the tag names a single step; one paragraph on p. 22 (PDF p. 37) breaks its lines differently in a build of the tag, because the sources tie its closing citation to the preceding word; the digest that the REST API reports for an asset carries an algorithm prefix, which the comparison with `SHA256SUMS` now strips; and CI compares the text on pushes and pull requests to `main` and when started by hand, not on every push.
- `scripts/compare_pdf_text.py`: its docstring describes the processing of the deposited file as `publication/README.md` does; the soft hyphen it drops is written as an escape sequence, so the script is ASCII, and the comparison is unchanged.
- `Makefile`: two builds of the same sources give the same bytes only in one directory, because the PDF identifier depends on it; no target writes Python's bytecode cache into the source tree any more, which the comment says is not written to; and `harness` builds in `evaluation/`, so that `evaluation/global.json` selects the SDK.
- `evaluation/docs/evaluation.md`: the measured numbers of Chapter 6 come from this code, not every number of the thesis; it names the paths of this repository, passes the image of the measurement (`fentwums/oss-cad-suite:2026-06-30`) explicitly and runs the `dotnet` commands in `evaluation/`; output is constrained to the benchmarking suite directory, not to the repository root; the integration report of the thesis is not in this repository; the Linux and Windows result files record no harness commit and the files of the cross-host control one that is in no history, so they do not fix the repository state; the measurement hygiene is given as recommendations, beside what the thesis records, not as the controls behind the reported confidence intervals; the evaluation is described by what it measured, the seven workloads run to success in the container and six artifacts of two designs byte-identical across three hosts and two image builds, an identity the pinned toolchain accounts for, with no container output compared with a native one, where the tag says that it tests a result unaltered against native execution and that its axes establish a machine-independent result, the portability claim realised; between the entries of its table, the critical value of the t distribution steps down to the nearest lower entry, where the tag says that it is interpolated; and the harness holds the defaults of the extension except four settings, among them the check of the named-pipe server, which it switches on, where the tag says that it carries the plugin's default settings and measures the architecture as shipped.
- `evaluation/docs/amd64-native-baseline-protocol.md`: the image is built for `linux/amd64` only and is on no registry, not published, and its limitations are linked at the pinned commit; it names the paths of this repository and runs the `dotnet` command in `evaluation/`; the macOS figures are the marginal cost of the extension, strategy against CLI, not an emulated upper bound; the result files record native versions of Yosys and Icarus Verilog only, not the parity conditions of every measurement; and the parity check rejected the native Windows toolchain.
- `evaluation/benchmarking_suite/README.md`: the measurement used `fentwums/oss-cad-suite:2026-06-30`, built locally and on no registry, not `fentwums/oss-cad-suite:latest`, and the native baseline is run with `--image` as well; it names the SDK the harness needs; the overhead reported for the macOS host is the strategy-against-CLI difference under the same emulation, not a figure that reflects emulation; and identical hashes show that the toolchain pinned in the image gives the same outputs on each host, and every iteration exited with code 0, where the tag calls the hashes direct evidence that the architecture makes tool outputs machine-independent and says that the toolchain executes correctly; and it asks for Python 3.9 to 3.12, the versions the three machines ran, because `run_evaluation.py` stops under Python 3.14, where the tag asks for Python 3.8 or later.
- `evaluation/examples/README.md`: the example projects are supplementary; the thesis does not cite them, and none of its figures comes from them; and no run of them is recorded, where the tag calls them the integration-test corpus whose passing runs confirm the container end to end and says that each compiles to a bitstream.
